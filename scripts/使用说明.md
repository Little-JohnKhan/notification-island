# 灵动岛 · 使用说明

> 构建 v45 · 适用 AutoJs6 6.7.0+ · Android 16（API 36）

---

## 一、它是怎么工作的

```
AutoJs6 脚本（island_daemon.js）一直在后台跑
        ↓ 读配置 → 判断该显示什么 → 发广播
外部 App（com.example.liveupdateverify）负责画岛
        ↓ 按钮被点击 → 广播回传 key
AutoJs6 收到 key → 执行按钮动作
```

结论：**岛不是本地通知，是外部 App 渲染的**。脚本只负责「什么时候、显示什么、按钮做什么」。

Android 的硬限制（脚本无法突破）：

| 限制 | 数值 |
|---|---|
| 短文本 `short` | ≤ 4 个字 |
| 按钮数量 | ≤ 3 个（有「切回」键时只剩 2 个） |
| 小图标 | 固定，脚本传了也无效 |

## 二、文件放哪

```
/storage/emulated/0/
└── 脚本/
    ├── 常用模块/
    │   ├── UI模块.js        ← 界面底座
    │   ├── UI扩展.js        ← 面板/选择器（应用选择器在这里）
    │   └── 上岛模块.js      ← 与上岛 App 通信
    └── 日常/
        ├── main.js          ← 可选，任务队列
        └── 灵动岛/
            ├── island_daemon.js   ← 守护，常驻
            ├── island_config.js   ← 配置页
            ├── island_kit.js      ← 公共函数库
            └── island_rules.json  ← 配置数据
```

这些路径在代码里是**写死**的，换位置要改多处。

### 启动与更新

| 操作 | 做法 |
|---|---|
| 启动守护 | 运行 `island_daemon.js` |
| 打开配置 | 运行 `island_config.js` |
| **更新文件后** | **必须重启守护**，否则还在跑内存里的旧代码 |

如何确认生效：配置页 → 设置 → 最底部「关于」→ 看构建号。

> 覆盖文件时注意：`island_kit.js`、`island_daemon.js`、`island_config.js` 在 **灵动岛/**；
> `UI模块.js`、`UI扩展.js`、`上岛模块.js` 在 **常用模块/**。放错就等于没更新。

## 三、三种岛与两层栈

**只有两层**，不是三级优先级：

```
上层：timerRule   ← 定时岛 和 通知岛 共用一个槽位
下层：fgRule      ← 应用岛
```

| 类型 | 触发条件 | 占哪一层 |
|---|---|---|
| 应用岛 | 前台应用命中规则 | 下层 |
| 定时岛 | 时间到（每天 / 每周 / 间隔） | 上层 |
| 通知岛 | 收到指定通知 | 上层 |

**上层只有「谁后到谁占」**：定时岛显示中来了通知，通知岛盖上去；通知岛显示中来定时时间，定时岛盖上去。

触发时一定会 `showTimer = true` **立刻置顶**，不存在「定时岛悄悄出现但被应用岛挡住、你根本不知道」的情况。

上层压着下层时，岛上会多一个「切回 xx」按钮。点它交换上下层，正文里可以用 `{left}` 显示上层剩余时间。

> 「切回」按钮只在**另一层真正可用**时出现。如果那一层被临时屏蔽了，按钮不会显示，不会留下点了没反应的空按钮。

### 应用岛

按**包名**匹配。同一个应用想出多个岛，用「类名包含」区分页面。

### 定时岛

| 类型 | 说明 |
|---|---|
| 每天 | 指定 HH:mm |
| 每周 | 指定星期几 + HH:mm |
| 间隔 | 每 N 分钟 |

「持续时间」决定岛留多久，0 = 一直显示。

**错过会补发**：息屏期间进程被系统冻结时，定时检查不会执行，可能整个触发点被错过。守护在亮屏时会回头检查「今天已过、但仍在持续时间内」的触发点并补上，且补发时用的是**原始结束时间**，不会从补发那一刻重新计时。

### 通知岛

监听系统通知，支持模板：

```
{app}   → 应用名
{title} → 通知标题
{text}  → 通知正文
```

**只匹配第三方应用**：选应用列表默认过滤系统应用。需要抓短信验证码这类场景，在「选择应用」面板点搜索框右边的 **「含系统应用」** 开关，打开后会出现「信息」等系统应用。

> ⚠️ HyperOS 的「验证码安全保护」开启时，通知内容会被系统隐藏，脚本拿不到数字。要抓验证码需要先关掉这个保护。

## 四、按钮动作

| 类型 | 作用 | value 填什么 |
|---|---|---|
| `task` | 交给 main.js 队列跑 | 脚本路径 |
| `script` | 直接启动脚本 | 脚本路径 |
| `code` | 执行一段 JS | 代码字符串 |
| `app` | 打开应用 | 包名 |
| `page` | 打开灵动岛配置页 | — |
| `hide` | 下岛 | — |
| `mute` | 临时屏蔽 N 分钟后恢复 | 分钟数 |
| `last` | 切回另一层 | — |

### 图标只有 4 个

```
dog   bear   rabbit   cat
```

填别的会退回到默认勾。

### 一个坑

**定时岛到点时，会自动执行 `script` 和 `task` 类型的按钮**（这是「到点执行」开关的机制）。所以别把「喝一杯」设成 `script`，否则岛一弹出来就自动加一杯。要用户手点的，用 `code`。

## 五、下岛 vs 临时屏蔽

这两个动作经常被混淆，行为完全不同：

| 动作 | 语义 | 什么时候会重新出现 |
|---|---|---|
| **下岛** | 撤掉，本次不再回来 | 定时岛/通知岛：下次触发时<br>应用岛：**离开并重新进入该应用** |
| **临时屏蔽** | 撤掉，N 分钟后自动回来 | 计时结束；或来了新的触发 |

### 下岛只撤「当前这一层」

| 当前显示 | 点「下岛」的结果 |
|---|---|
| 定时岛 / 通知岛（上层） | 只撤这一层，**应用岛自动浮现** |
| 应用岛（最底层） | 整体下岛，并屏蔽到离开当前应用为止 |

应用岛被屏蔽后，只要你**切到别的应用或回桌面**，屏蔽就解除了，切回来照常显示。这个机制是为了防止「刚点下岛，岛立刻又弹回来」。

### 临时屏蔽只作用于「你正在看的这一层」

这是关键：**两层各有独立的屏蔽计时，互不影响**。

| 你的操作 | 结果 |
|---|---|
| 屏蔽定时岛（应用岛还在下面） | 定时岛消失，**应用岛立刻浮现**；定时岛继续计时 |
| 屏蔽定时岛后切到别的应用 | 应用岛正常显示，定时岛仍在屏蔽 |
| 屏蔽应用岛 | 应用岛消失（没有下层可回落） |

### 屏蔽期间的计时：暂停，不是重置

```
定时岛设了持续 5 分钟
第 0 分钟：点上岛
第 0 分钟：点「临时屏蔽 6 分钟」
        → 结束时间顺延到第 11 分钟
第 6 分钟：岛回来，还剩 5 分钟
第 11 分钟：正常结束
```

也就是说**屏蔽期间计时暂停**，恢复后完整走完剩余时长。这保证了「按钮设的时长优先于规则里的持续时间」，不会出现「刚回来就立刻过期消失」。

### 重触发会放行

来了新的匹配通知、或到了下一个定时触发点，**那一层的屏蔽会自动解除**。屏蔽表达的是「这次不想看」，不是「永不显示」。

## 六、变量（重点）

岛内容里可以写 `{变量名}`，渲染时替换成真实值。

```
今天第 {water} 杯 · 目标 8
        ↓ 渲染
今天第 3 杯 · 目标 8
```

### 6.1 内置变量

| 变量 | 示例值 | 说明 |
|---|---|---|
| `{time}` | `16:06` | 当前时间 |
| `{date}` | `10/19` | 月/日 |
| `{hour}` `{min}` `{sec}` | `16` `6` `33` | |
| `{left}` | `15` | **上层定时岛的剩余分钟数**，无定时岛时为 0 |
| `{app}` `{title}` `{text}` | — | 仅通知岛有值 |

### 6.2 倒计时用 `{left}`

倒计时不再是自动附加的，要用变量自己写：

| 你写的 | 显示 |
|---|---|
| `剩余{left}分钟` | 剩余 15 分钟 |
| `倒计时{left}` | 倒计时 15 |
| `还有{left}分，加油` | 还有 15 分，加油 |

不写 `{left}` 就不会显示倒计时。这样你可以自己决定要不要显示、显示成什么样。

> ⚠️ 注意 `{time}` 已经被占用（表示当前时间 `HH:MM`），不要拿它当倒计时。

### 6.3 自定义变量

变量**存在手机里**（SharedPreferences 的 `island_vars`），不是内存变量。因为每次点按钮都是一个新的脚本实例，内存变量会清零。

```js
var kit = require("/storage/emulated/0/脚本/日常/灵动岛/island_kit.js");

kit.setVar("water", 3);            // 写
kit.getVar("water", 0);            // 读，没有则返回 0
kit.clearVar("water");             // 删
```

### 6.4 按天归零（喝水这类场景）

```js
kit.setVar("water", 值, { daily: true });
```

原理：写入时额外存一个 `water__day = 今天`。读取时如果日期不是今天，直接当作 0。

**不需要定时任务、不需要额外脚本**，第二天打开自动从 0 开始。

### 6.5 完整的喝水例子

**定时岛内容**

```
今天第 {water} 杯 · 目标 8
```

**按钮「喝一杯」· 类型 code**

```js
var kit = require("/storage/emulated/0/脚本/日常/灵动岛/island_kit.js");
kit.setVar("water", Number(kit.getVar("water", 0)) + 1, { daily: true });
kit.hideTimerIsland();   // 记完就收起定时岛，回到应用岛/默认态
```

**按钮「重置」· 类型 code**

```js
var kit = require("/storage/emulated/0/脚本/日常/灵动岛/island_kit.js");
kit.setVar("water", 0, { daily: true });
```

### 6.6 什么时候刷新

| 写法 | 何时更新 |
|---|---|
| `kit.setVar(名, 值)` | 立刻 |
| `kit.setVar(名, 值, true)` | 不刷新（静默） |
| 点「code」按钮 | 执行完自动刷新 |
| 直接改 storages | 不会刷新 |

> 注意：`setVar` 的第三个参数，`true` 是静默，`{daily:true}` 是按天，两者都要就写 `{ daily: true, silent: true }`。

### 6.7 没替换？

- 显示 `{water}` → 变量还没写入，或名字拼错
- 变量名只能是**字母、数字、下划线**，中文不行（`{water杯}` 无效）

## 七、code 按钮可以直接写 mute / hide

`code` 按钮执行的代码里，**已经预置了两个函数**，不需要 require 任何东西：

```js
mute(10)     // 临时屏蔽 10 分钟
```

```js
hide()       // 等同「下岛」
```

也可以组合判断：

```js
if (currentPackage() === "com.tencent.mm") mute(5);
else hide();
```

原理：这两个函数通过 `storages` 的命令通道和守护通信（守护每秒轮询一次），所以能操作守护的内存状态。命令会在 1 秒内生效。

## 八、脚本 API 一览

```js
var kit = require("/storage/emulated/0/脚本/日常/灵动岛/island_kit.js");
```

| 方法 | 作用 |
|---|---|
| `setVar(名, 值[, 选项])` | 写变量 |
| `getVar(名, 默认值)` | 读变量 |
| `clearVar(名)` | 删变量 |
| `hideTimerIsland()` | 收起定时岛，回应用岛/默认态 |
| `hideIslandNow()` | 直接发 STOP 撤岛（不经过守护） |
| `testShow()` | 绕过规则，试发一次岛 |
| `launchScript(path)` | 启动脚本 |
| `launchTask(name, path)` | 交给 main.js 队列（**需要 main.js 存在**） |
| `openConfig()` | 打开配置页 |
| `sendCmd(action)` | 发命令给守护 |
| `readState()` | 读守护状态（含当前岛信息） |
| `daemonAlive()` | 守护还活着吗 |

`sendCmd` 可用的 action：

```
reload      重读配置并重绘
hide        下岛（同 hide 动作）
muteFor     临时屏蔽，需传 min
showTimer   强制显示定时岛
showFg      切回应用岛
hideTimer   收起定时岛
```

## 九、设置页每一项

| 项 | 含义 | 建议 |
|---|---|---|
| 未命中规则时 | 显示默认态 / 撤岛 / 保持不动 | **撤岛**（默认值，长时间显示会受系统活跃度限制） |
| 判定延迟 | 未命中后等多久才切默认态 | 350 ms，防切换抖动 |
| 回桌面判定 | 回桌面后等多久再确认 | 400~800 ms |
| 保持上限 | 「保持不动」最多保持多久 | 0 = 不限 |
| 事件兜底轮询 | 事件丢了用前台查询纠正 | 5 秒 |
| 息屏隐藏岛 | 灭屏撤岛，亮屏恢复 | **开** |
| 仅亮屏时工作 | 熄屏时不跑前台判断 | 开 |
| 点击调试 | 点岛时 toast 出 key | 排查按钮用 |

> 「手动下岛抑制时长」已移除。下岛和临时屏蔽现在是两个独立动作，时长直接在按钮里配。

## 十、已知限制（改不了）

**0. 系统会「谎报」前台（已用控件树兜底）**

熄屏久、长时间不操作时，系统可能把 `currentPackage` 报成桌面或 SystemUI，实际还在原应用。守护在回桌面判定和输入法反查时会先扫一次活动窗口的控件树，按包名节点数判断真实前台，扫不到才回退旧逻辑。

**1. 后台卡片页会把岛和状态栏一起藏起来**

HyperOS 的最近任务界面是沉浸式全屏，系统连状态栏都隐藏，岛自然一起藏。从卡片回到应用时会有短暂空窗，这是系统行为，代码只能「回来时重发一次」，无法提前。

**2. 息屏久了定时不准**

Android Doze 会推迟定时器，可能晚几分钟。现在有亮屏补发机制兜底，但仅对「仍在持续时间内」的触发点有效。

**3. 岛会被系统降级**

Live Update 久不更新会被判定不活跃。目前没有有效的脚本侧补救手段。

## 十一、排错顺序

1. **配置页能打开吗** → 打不开是语法错误或模块路径问题
2. **构建号对不对** → 设置→关于，和你覆盖的版本一致吗
3. **守护在跑吗** → 设置→诊断→最近收到事件，秒数在涨就正常
4. **最近窗口事件** → 看 daemon 最后收到的包名/类名，判断是不是你预期的应用
5. **按钮点了没反应** → 打开「点击调试」，看 key 和显示的按钮对不对

改完文件后永远记得：

```
覆盖 → 重启守护 → 确认构建号
```
