# 灵动岛 · 使用说明

> 构建 v37 · 适用 AutoJs6 6.7.0+ · Android 16（API 36）

---

## 一、它是怎么工作的

```
AutoJs6 脚本（island_daemon.js）一直在后台跑
        ↓ 读配置 → 判断该显示什么 → 发广播
外部 App（com.example.liveupdateverify）负责画岛
        ↓ 按钮被点击 → 广播回传 key
AutoJs6 收到 key → 执行按钮动作
```

结论：**岛不是本地通知，是外部 App 渲染的**。脚本只负责「什么时候、显示什么、按钮做什么」。

Android 的硬限制（脚本无法突破）：

| 限制 | 数值 |
|---|---|
| 短文本 `short` | ≤ 4 个字 |
| 按钮数量 | ≤ 3 个（有「切换」键时只剩 2 个） |
| 小图标 | 固定，脚本传了也无效 |

## 二、文件放哪

```
/storage/emulated/0/
└── 脚本/
    ├── 常用模块/
    │   ├── UI模块.js        ← 界面底座
    │   ├── UI扩展.js        ← 面板/选择器
    │   └── 上岛模块.js      ← 与上岛 App 通信
    └── 日常/
        ├── main.js          ← 可选，任务队列
        └── 灵动岛/
            ├── island_daemon.js   ← 守护，常驻
            ├── island_config.js   ← 配置页
            ├── island_kit.js      ← 公共函数库
            └── island_rules.json  ← 配置数据
```

这些路径在代码里是**写死**的，换位置要改多处。

### 启动与更新

| 操作 | 做法 |
|---|---|
| 启动守护 | 运行 `island_daemon.js` |
| 打开配置 | 运行 `island_config.js` |
| **更新文件后** | **必须重启守护**，否则还在跑内存里的旧代码 |

如何确认生效：配置页 → 设置 → 最底部「关于」→ 看构建号。

## 三、三种岛

| 类型 | 触发条件 | 优先级 |
|---|---|---|
| 应用岛 | 前台应用命中规则 | 低 |
| 定时岛 | 时间到（每天/每周/间隔） | 中（盖住应用岛，留「切回」键） |
| 通知岛 | 收到指定通知 | 高（本质是定时岛的一种） |

### 应用岛

按**包名**匹配。同一个应用想出多个岛，用「类名包含」区分页面。

### 定时岛

| 类型 | 说明 |
|---|---|
| 每天 | 指定 HH:mm |
| 每周 | 指定星期几 + HH:mm |
| 间隔 | 每 N 分钟 |

「持续时间」决定岛留多久，0 = 一直显示。

### 通知岛

监听系统通知，支持模板：

```
{app}   → 应用名
{title} → 通知标题
{text}  → 通知正文
```

## 四、按钮动作

| 类型 | 作用 | value 填什么 |
|---|---|---|
| `task` | 交给 main.js 队列跑 | 脚本路径 |
| `script` | 直接启动脚本 | 脚本路径 |
| `code` | 执行一段 JS | 代码字符串 |
| `app` | 打开应用 | 包名 |
| `page` | 打开灵动岛配置页 | — |
| `hide` | 下岛 | — |
| `last` | 切回上一层（定时岛 ↔ 应用岛） | — |

### 图标只有 4 个

```
dog   bear   rabbit   cat
```

填别的会退回到默认勾。

### 一个坑

**定时岛到点时，会自动执行 `script` 和 `task` 类型的按钮**（这是「自动跑任务」的机制）。所以别把「喝一杯」设成 `script`，否则岛一弹出来就自动加一杯。要用户手点的，用 `code`。

## 五、变量（重点）

岛内容里可以写 `{变量名}`，渲染时替换成真实值。

```
今天第 {water} 杯 · 目标 8
        ↓ 渲染
今天第 3 杯 · 目标 8
```

### 5.1 内置变量

| 变量 | 示例值 |
|---|---|
| `{time}` | `16:06` |
| `{date}` | `10/19` |
| `{hour}` `{min}` `{sec}` | `16` `6` `33` |
| `{app}` `{title}` `{text}` | 仅通知岛有值 |

### 5.2 自定义变量

变量**存在手机里**（SharedPreferences 的 `island_vars`），不是内存变量。因为每次点按钮都是一个新的脚本实例，内存变量会清零。

```js
var kit = require("/storage/emulated/0/脚本/日常/灵动岛/island_kit.js");

kit.setVar("water", 3);            // 写
kit.getVar("water", 0);            // 读，没有则返回 0
kit.clearVar("water");             // 删
```

然后在岛内容里写：

```
今天第 {water} 杯
```

### 5.3 按天归零（喝水这类场景）

```js
kit.setVar("water", 值, { daily: true });
```

原理：写入时额外存一个 `water__day = 今天`。读取时如果日期不是今天，直接当作 0。

**不需要定时任务、不需要额外脚本**，第二天打开自动从 0 开始。

### 5.4 完整的喝水例子

**定时岛内容**

```
今天第 {water} 杯 · 目标 8
```

**按钮「喝一杯」· 类型 code**

```js
var kit = require("/storage/emulated/0/脚本/日常/灵动岛/island_kit.js");
kit.setVar("water", Number(kit.getVar("water", 0)) + 1, { daily: true });
kit.hideTimerIsland();   // 记完就收起定时岛，回到应用岛/默认态
```

**按钮「重置」· 类型 code**

```js
var kit = require("/storage/emulated/0/脚本/日常/灵动岛/island_kit.js");
kit.setVar("water", 0, { daily: true });
```

### 5.5 什么时候刷新

| 写法 | 何时更新 |
|---|---|
| `kit.setVar(名, 值)` | 立刻 |
| `kit.setVar(名, 值, true)` | 不刷新（静默） |
| 点「code」按钮 | 执行完 400ms 自动刷新 |
| 直接改 storages | 不会刷新 |

> 注意：`setVar` 的第三个参数，`true` 是静默，`{daily:true}` 是按天，两者都要就写 `{ daily: true, silent: true }`。

### 5.6 没替换？

- 显示 `{water}` → 变量还没写入，或名字拼错
- 变量名只能是**字母、数字、下划线**，中文不行（`{water杯}` 无效）

## 六、脚本 API 一览

```js
var kit = require("/storage/emulated/0/脚本/日常/灵动岛/island_kit.js");
```

| 方法 | 作用 |
|---|---|
| `setVar(名, 值[, 选项])` | 写变量 |
| `getVar(名, 默认值)` | 读变量 |
| `clearVar(名)` | 删变量 |
| `hideTimerIsland()` | 收起定时岛，回应用岛/默认态 |
| `hideIslandNow()` | 直接发 STOP 撤岛（不抑制，下次事件可能又上岛） |
| `testShow()` | 绕过规则，试发一次岛 |
| `launchScript(path)` | 启动脚本 |
| `launchTask(name, path)` | 交给 main.js 队列 |
| `openConfig()` | 打开配置页 |
| `sendCmd(action)` | 发命令给守护 |
| `readState()` | 读守护状态（含当前岛信息） |
| `daemonAlive()` | 守护还活着吗 |

`sendCmd` 可用的 action：

```
reload      重读配置并重绘
hide        撤岛 + 抑制
showTimer   强制显示定时岛
showFg      切回应用岛
hideTimer   收起定时岛
```

## 七、设置页每一项

| 项 | 含义 | 建议 |
|---|---|---|
| 未命中规则时 | 显示默认态 / 撤岛 / 保持不动 | **保持不动**（实测最稳，减少状态切换） |
| 手动下岛抑制时长 | 下岛后多久不再自动上岛 | 10 分钟 |
| 判定延迟 | 未命中后等多久才切默认态 | 350 ms，防切换抖动 |
| 回桌面判定 | 回桌面后等多久再确认 | 400~800 ms |
| 保持上限 | 「保持不动」最多保持多久 | 0 = 不限 |
| 事件兜底轮询 | 事件丢了用前台查询纠正 | 5 秒 |
| 息屏隐藏岛 | 灭屏撤岛，亮屏恢复 | **开**（减少息屏期间的无效刷新） |
| 仅亮屏时工作 | 熄屏时不跑前台判断 | 开 |
| 点击调试 | 点岛时 toast 出 key | 排查按钮用 |

## 八、已知限制（改不了）

**0. 系统会「谎报」前台（已用控件树兜底）**

熄屏久、长时间不操作时，系统可能把 `currentPackage` 报成桌面或 SystemUI，实际还在原应用。
v40 起，回桌面判定和输入法反查会先扫一次活动窗口的控件树，按包名节点数判断真实前台，扫不到才回退旧逻辑。

**1. 后台卡片页会把岛和状态栏一起藏起来**

HyperOS 的最近任务界面是沉浸式全屏，系统连状态栏都隐藏，岛自然一起藏。从卡片回到应用时会有短暂空窗，这是系统行为，代码只能「回来时重发一次」，无法提前。

**2. 熄屏久了定时不准**

Android Doze 会推迟定时器，可能晚几分钟。脚本没有唤醒锁权限。

**3. 岛会被系统降级**

Live Update 久不更新会被判定不活跃。目前没有有效的脚本侧补救手段（试过，无效，已移除）。

## 九、排错顺序

1. **配置页能打开吗** → 打不开是语法错误或模块路径问题
2. **构建号对不对** → 设置→关于，和你覆盖的版本一致吗
3. **守护在跑吗** → 设置→诊断→最近收到事件，秒数在涨就正常
4. **最近窗口事件** → 看 daemon 最后收到的包名/类名，判断是不是你预期的应用
5. **按钮点了没反应** → 打开「点击调试」，看 key 和显示的按钮对不对

改完文件后永远记得：

```
覆盖 → 重启守护 → 确认构建号
```
